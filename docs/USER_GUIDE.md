## 1. Реєстрація (Sign Up)

**Призначення:** створення нового акаунту.

**Позитивний шлях:**
1. **Full Name** — ім'я та прізвище з великих літер через пробіл (напр. `Olena Kovalenko`).
2. **Email** — лише малими літерами, лише `@gmail.com`.
3. **Password** — мінімум 8 символів, щонайменше 1 велика літера.
4. **Confirm Password** — має збігатися з паролем.
5. Постав **GDPR-чекбокс** згоди.
6. Натисни **Create account** → токен зберігається → перехід на **Group Setup** (новий юзер ще без групи).

**Негативні шляхи:**

| Дія | Результат |
|---|---|
| Email з великою літерою | `Email must be lowercase — capital letters are not allowed` |
| Не-Gmail адреса | `Enter a valid Gmail address (@gmail.com)` |
| Ім'я з малої / одне слово | `Enter your first and last name with a capital letter…` |
| Пароль < 8 або без великої | відповідна inline-помилка |
| Паролі не збігаються | `Passwords do not match` |
| Не поставлено GDPR-згоду | помилка чекбокса |
| Email уже існує | 409 → `User with this email already exists` |
| 5 невдалих спроб поспіль | локальне блокування на 15 хв із відліком |

Примітка: реєстрація має локальний rate-limit (UX-захист); бекенд rate-limit діє на логін.

## 2. Логін (Login)

**Призначення:** вхід в акаунт.

**Позитивний шлях:** введи email + пароль → **Log in**. Маршрутизація залежно від кількості груп:
- **0 груп** → Group Setup;
- **1 група** → одразу Feed (група стає активною);
- **кілька** → екран вибору групи (Select Group).
- Якщо зайшла за **secret-gift лінком** — після входу повертає **саме на той лінк**.

**Негативні шляхи:**

| Дія | Результат |
|---|---|
| Невірний email/пароль | `Invalid email or password` (узагальнено — захист від перебору акаунтів) |
| Забагато спроб (5 за 15 хв, per-IP) | 429 + блок форми з **точним відліком `m:ss`** (синхронізовано з беком через заголовок `Retry-After`) |
| Порожні поля | кнопка неактивна |

## 3. Групи та учасники (Invite / Remove Member)

**Запрошення через лінк (тільки Admin):**

Settings → Members, або модалка **Invite member** на Feed → **Generate Link** → лінк із терміном дії (TTL) → **Copy** → надсилаєш людині. Вона приєднується, вставивши лінк у Group Setup.

Не-Admin намагається згенерувати → **403** `Only Admin can generate invite links`.

**Приєднання до групи:** вставити отриманий лінк у Group Setup → приєднання.

**Обмеження (бекенд-endpoint відсутній):**
- **Remove member** — показує `Remove member endpoint not available yet` (видалення учасника ще не реалізоване на сервері).
- Запрошення **по email напряму** прибрано з інтерфейсу (працює лише запрошення через лінк).

## 4. Картки (Connect / Disconnect Card)

**Підключення (Connect):**

**Позитивний шлях:**
1. **Connect Card** → введи **Monobank personal token** (формат `uXXXX…`).
2. Крок 1: підтягуються доступні картки (`/monobank/client-info`).
3. Крок 2: обери картку → **Connect** (`/monobank/connect`).

**Негативні шляхи:**

| Дія | Результат |
|---|---|
| Невірний/прострочений токен | помилка валідації від банку |
| Повторний запит < 60 с | Monobank-ліміт **1 запит / 60 с** → треба зачекати |
| Немає карток у банку | відповідне повідомлення |

**Відключення (Disconnect):** Card Details → **Disconnect** (`DELETE /monobank/card/{id}`).

Чужа картка → **403**; картку не знайдено → **404**.

**Важливо:** доки **не підключиш ВЛАСНУ** картку — стрічка групи недоступна (показується заглушка «підключіть свою картку», а не транзакції).

## 5. Запит коштів (Money Request)

**Призначення:** попросити гроші в іншого учасника групи.

**Позитивний шлях:**
1. Біля учасника натисни **$** → модалка запиту → сума + (опц.) опис → **Send**.
2. Отримувач бачить запит у **правій панелі Feed** → **Accept** (треба **обрати картку**, з якої платить) або **Decline**.
3. При Accept — віртуальний переказ з обраної картки отримувача на картку запитувача.
4. Запитувач у реальному часі отримує **модалку-відповідь** (прийнято/відхилено).

**Негативні шляхи:**

| Дія | Результат |
|---|---|
| Accept без вибору картки | 400 `Необхідно вибрати картку для оплати` |
| Недостатньо коштів на обраній картці | 400 `Недостатньо коштів` |
| Запит уже вирішено | 409 `Запит вже вирішено` |
| В отримувача немає активної картки | 400 |

## 6. Переказ картка→картка (Transfer)

**Призначення:** миттєвий віртуальний переказ між картками учасників групи.

**Позитивний шлях:** **Transfer** → обери **картку-відправника** (свою активну) і **картку-отримувача** (будь-яку активну в групі) → сума → (опц.) категорія/опис → **Send**.
- Створюються 2 записи (списання + зарахування), і переказ **push-ом зʼявляється у стрічці всіх учасників**.

**Негативні шляхи:**

| Дія | Результат |
|---|---|
| Недостатньо коштів | 400 `Недостатньо коштів` |
| Та сама картка | 400 `Не можна переказувати на ту саму картку` |
| Картки різних груп | 400 |
| Деактивована картка | 400 |
| > 30 переказів/хв | 429 (rate-limit) |

Примітка: один переказ = **два рядки** у стрічці (списання у відправника + зарахування в отримувача).

## 7. Secret Gift — створення події

**Призначення:** таємний збір коштів на подарунок імениннику (target не бачить збору до розкриття).

**Позитивний шлях:** **Gift Events** → створити подію:
- **Target user** — кому дарунок (не собі).
- **Name** — ≥ 3 символи.
- **Unlock date** — мінімум **завтра 00:00**.
- **Goal** — ≥ 100 UAH.
- Після створення подія **ACTIVE**; згенеруй **invite-лінк** і поділись із родиною (тільки організатор).

**Негативні шляхи:**

| Дія | Результат |
|---|---|
| Target = ти сам | 400 `You cannot be the recipient` |
| Назва < 3 символи | inline-помилка |
| Дата в минулому | заблоковано (min) + `Date must be in the future` |
| Goal < 100 | `Goal must be at least 100 UAH` |

**Повний шлях secret-gift лінку:** анонім відкриває лінк → редірект на логін → вводить дані → **модалка «Do you want to join this Secret Gift?»** → **Yes, join** → екран деталей події.

Не-учасник групи іменинника → **403** (`you are not a member of this group`); прострочений лінк → **404**.

---

## 8. Деталі події (Event Details)

**Організатор / донор бачить:** прогрес (зібрано / ціль), invite-лінк (організатор), блок **Contribute**, список донорів.

**Іменинник (target):**
- До розкриття → **403** (сюрприз прихований — ізоляція).
- Після розкриття → **«wow»-екран**: зібрана сума, хто скинувся, конфеті.

Скасована / неіснуюча подія → **404**.

Примітка: ізоляція прив'язана до **статусу події** (ACTIVE → прихована для таргета; REVEALED → видима), що стійко до таймзон і затримки cron.

---

## 9. Внесок на подарунок (Contribute)

**Позитивний шлях:** на деталях події → **Make a contribution** → сума (1–100 000) + обери свою картку → **Contribute**.
- Створюється **секретна транзакція** (списання), прихована від іменинника; push оновлює стрічку решти учасників.

**Негативні шляхи:**

| Дія | Результат |
|---|---|
| Ти — іменинник | 400 `Ви не можете донатити на свій же сюрприз` |
| Збір закрито (не ACTIVE) | 400 `Збір вже закрито` |
| Час збору минув | 400 `Час збору вже минув` |
| Сума ≤ 0 або > 100000 | 400 `Невалідна сума внеску` |
| Картка не твоя | 403 `Картка вам не належить` |
| Немає підключеної картки | підказка підключити картку на Feed |

Примітка: внесок зʼявляється у стрічці контриб'юторів, але **ніколи** у стрічці іменинника.

## 10. Аналітика витрат (Spendings by Categories)

**Призначення:** донат-діаграма витрат за категоріями (права панель Feed).
- Враховуються **лише витрати** (від'ємні суми).
- Категорія визначається за slug/назвою → **стабільний колір** (одна категорія = завжди той самий колір).

**Порожній стан:** `No spending to analyze yet`, якщо витрат немає.

## 11. Сповіщення (Notifications)

У застосунку **два** типи сповіщень:

**Secret Gift — push & email:**
- нагадування **за 24 години** до розкриття;
- нагадування **в день розкриття**;
- сповіщення **в момент розкриття** подарунка.

Нагадування йдуть усім у групі, **крім іменинника**. Browser-push потребує дозволу на сповіщення; ці події завжди є і в **in-app списку** (sidebar).

**Real-time оновлення стрічки:**
- нові транзакції та перекази картка→картка;
- вхідні money-requests;
- emoji-реакції.

Зʼявляються миттєво у Feed через живе зʼєднання (WebSocket) — без жодних налаштувань.

In-app список сповіщень **не оновлюється в реальному часі** — щоб побачити новий запис, перезавантаж сторінку. Кнопка **Mark all read** позначає всі прочитаними.

## 12. Settings

**Members** — список учасників групи + твоя роль (**Admin** / **Member**, бейдж). Генерація invite-лінку — тільки Admin (Member бачить заглушку).

**Connected Cards** — перелік підключених карток групи.

**Notifications** — інформаційний опис типів сповіщень (див. розділ 11). Без перемикачів — сповіщення працюють автоматично.

**Privacy & Data** — інформація про шифрування даних і посилання на Privacy Policy (GDPR).

---

## Наскрізні принципи

- **Порожні стани:** усюди, де даних немає, показується повідомлення/заглушка, а не безкінечний лоадер.
- **Error Boundary:** помилка рендеру однієї сторінки показує fallback-екран із кнопками **Retry / Reload**, а не кладе весь застосунок.
- **Real-time:** нові транзакції/реакції/запити приходять через WebSocket (push у Feed); список сповіщень — лише при перезавантаженні.
- **Безпека входу:** rate-limit на логін (5 / 15 хв per-IP, із синхронним відліком на фронті) + локальний на реєстрацію.
- **Ізоляція Secret Gift:** іменинник не бачить ні події, ні внесків до розкриття.
