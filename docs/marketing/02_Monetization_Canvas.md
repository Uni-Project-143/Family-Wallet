# Family Wallet — Monetization Canvas


> «Трансформація коду в гроші». Усі цінові гіпотези спираються на реально реалізовані фічі (див. `01_Product_Strategy_Document.md`) та галузеві бенчмарки.

## Частина 1. Value Proposition (Feature → Benefit)

Беремо 3 найсильніші **технічні** фічі та перекладаємо їх на мову **вигоди для користувача**.

| # | Технічна фіча (що реалізовано в коді) | Вигода для користувача (Benefit) |
|---|---|---|
| 1 | **AES-256-GCM шифрування** Monobank-токена + read-only доступ + bcrypt + token blacklist (`core/encryption.py`, `core/security.py`) | «Ваші банківські дані захищені за банківським стандартом: токен зашифрований, доступ — лише на читання, ми ніколи не зможемо зняти ваші гроші.» |
| 2 | **Real-time стрічка через WebSocket** з авто-категоризацією за MCC і дедублікацією webhook (`core/websockets.py`, `monobank_service.py`) | «Бачте всі витрати родини в ту ж секунду, коли вони сталися — без оновлення сторінки, без ручного вводу, з автоматичними категоріями.» |
| 3 | **Secret Gift із серверною ізоляцією** (фільтр `$nor`, cron-розкриття, авто-переказ) (`gift_service.py`, `api/gift.py`) | «Скидайтеся на подарунок усією родиною так, щоб іменинник нічого не запідозрив — система сама збере, приховає й вручить суму в потрібний день.» |

## Частина 2. Unique Selling Proposition (USP)

**Формула:** *Ми допомагаємо (Цільова аудиторія) вирішити (Проблема) за допомогою (Технічна фіча).*

> **USP (інженерне формулювання):**
> Ми допомагаємо **українським родинам із картками Monobank** вирішити **проблему непрозорості спільних витрат і незручності організації сюрпризів** за допомогою **real-time стрічки транзакцій (WebSocket + Monobank webhook), захищеної AES-256, та унікальної механіки Secret Gift із серверною ізоляцією від іменинника.**

> **USP (маркетинговий слоган, 1 речення):**
> **«Family Wallet — єдиний застосунок, що показує витрати всієї родини наживо й дозволяє таємно зібрати на подарунок так, щоб іменинник нічого не дізнався — із банківським рівнем захисту ваших даних.»**

## Частина 3. Pricing Strategy (Стратегія ціноутворення)

### 3.1. Тип продукту та обрана модель

- **Тип:** B2C consumer FinTech, SaaS-доставка (web).
- **Обрана модель:** **Freemium + Subscription** (місячна/річна підписка з безкоштовним базовим рівнем).
- **Чому саме вона:**
  - Фінансові застосунки потребують **довіри** → безкоштовний вхід знижає бар'єр і дає час оцінити безпеку (AES-256, read-only токен).
  - Найсильніші фічі (**Secret Gift**, мультигрупи, історія) природно стають **приводом для апгрейду**, не ламаючи базову цінність.
  - Freemium підсилює **віральність**: Secret Gift запрошує нових людей у безкоштовний рівень, частина конвертується в Pro.

### 3.2. Порівняльний аналіз цін конкурентів

| Конкурент | Модель | Орієнтовна ціна | Позиція Family Wallet |
|---|---|---|---|
| Monobank «Банка/спільний доступ» | Безкоштовно (всередині банку) | 0 ₴ | Конкуруємо **цінністю** (Secret Gift, крос-функції), а не ціною |
| Honeydue | Freemium (Honeydue+) | ~$5–6 / міс | Аналогічний прайс, але ширша соціальна цінність |
| Spendee | Freemium / Premium / Plus | ~$2.5–4 / міс (Premium) | Трохи дорожче Spendee Premium, бо нішевий social+gift функціонал |
| Splitwise | Freemium / Pro | ~$3 / міс | Інша ніша (розподіл рахунків), беремо комплексністю |

**Цінове позиціонування:** **не демпінг і не преміум**, а **середній сегмент із преміальною унікальною фічею**. Pro дешевший за Honeydue+, але дорожчий за Spendee Premium — виправдано наявністю Secret Gift, real-time стрічки та локальної Monobank-інтеграції.

|---|---|---|---|

### 3.4. Monetization Hooks (де технічно вмикається платність)

| Hook | Технічна реалізація гейту | Тариф |
|---|---|---|

## Частина 4. Customer Acquisition Cost (CAC) — гіпотеза

> Це **математичне моделювання (Pre-launch Validation)**, а не фактичні витрати. Мета — довести розуміння економіки залучення.

### 4.1. Галузевий бенчмарк (Benchmarks)

- Згідно з публічними звітами (FirstPageSage / Demandsage, **Average CAC for FinTech/Consumer Apps 2025–2026**), CAC для B2C-фінтеху коливається в межах **$40–200** за платного клієнта; для consumer mobile/web fintech — нижній край діапазону.
- **Гіпотеза:** завдяки нашому USP (вірусний Secret Gift + локальна довіра до Monobank + нижчий CPC в Україні) ми **зменшимо CAC до ~$15–25 за платного користувача** — суттєво нижче галузевого медіану.

### 4.2. Канал 1 — Paid Ads (Meta: Facebook / Instagram)

Українська аудиторія, наочний продукт → орієнтуємось на нижній CPC.

```
Бюджет кампанії           : $200
CPC (середній, UA)         : $0.20
→ Кліків                   : 200 / 0.20 = 1 000
Конверсія клік → реєстрація: 5%
→ Безкоштовних реєстрацій  : 1 000 × 5% = 50
CAC за безкоштовного юзера : $200 / 50 = $4.00

Конверсія Free → Pro       : 4% (freemium-бенчмарк 3–5%)
→ Платних клієнтів         : 50 × 4% = 2
CAC за ПЛАТНОГО клієнта    : $200 / 2 = $100.00
```
**Висновок по каналу 1:** дорогий «холодний» канал; виправданий лише в парі з віральним підсиленням і ретеншном.

### 4.3. Канал 2 — Referral + Organic (Secret Gift virality + DOU/Reddit)

Кожен Secret Gift запрошує реальних родичів → природна вірусність (низький CAC).

**Organic-складова (вартість часу):**
```
Стаття на DOU/Reddit       : 10 год роботи розробника × $15/год = $150
Користувачів зі статті      : 15 реєстрацій
CAC (organic)              : $150 / 15 = $10.00 за реєстрацію
```

**Referral-складова (Secret Gift):**
```
Бонус за приведеного друга : $1.5 (внутрішній кредит / промо)
Учасників на 1 Secret Gift : ~4 (запрошених у групу)
Реєстрацій з 1 події       : 3 нові
Вартість бонусів           : 3 × $1.5 = $4.5
CAC (referral)             : $4.5 / 3 = $1.50 за реєстрацію
```
**Висновок по каналу 2:** найдешевший канал; **referral CAC ≈ $1.5** — драйвер зростання.

### 4.4. Зведена гіпотеза для перших 1 000 користувачів

| Канал | Частка | Реєстрацій | CAC/реєстрація | Бюджет |
|---|---:|---:|---:|---:|
| Meta Ads | 40% | 400 | $4.00 | $1 600 |
| Referral (Secret Gift) | 40% | 400 | $1.50 | $600 |
| Organic (DOU/Reddit) | 20% | 200 | $10.00 | $2 000 |
| **Разом** | **100%** | **1 000** | **$4.20 (зважений)** | **$4 200** |

> **Гіпотеза:** «На залучення перших **1 000** користувачів нам потрібно ≈ **$4.2 за реєстрацію** (зважений CAC) ≈ **$4 200 загалом**. За freemium-конверсії 4% це ~40 платних клієнтів, тобто **CAC за платного клієнта ≈ $105** на старті, що знижуватиметься до **$15–25** із посиленням віральності Secret Gift та ретеншну.»

### 4.5. Юніт-економіка (sanity-check проти LTV)

```
ARPU (Pro)                 : 149 ₴/міс ≈ $3.9/міс
Очікуваний строк життя     : 12 міс (припущення)
LTV (валовий)              : $3.9 × 12 = $46.8
Цільовий CAC (платний)     : $15–25
LTV / CAC                  : 1.9× – 3.1×  → здорове співвідношення (ціль ≥ 3×)
```
**Висновок:** при зрілому міксі каналів модель сходиться (LTV/CAC прямує до 3×). Ключ — **знизити частку дорогого Meta Ads** і **максимізувати referral через Secret Gift**, який є вбудованим у продукт вірусним механізмом.

## Частина 5. Open Source / fallback-нота

Якщо проєкт релізиться як **open source**, монетизація зберігається через: (а) **платну хмарну версію** (Pro/Family+ як managed-хостинг), (б) **донати / GitHub Sponsors**, (в) **кастомну розробку та інтеграції для банків (white-label)**, (г) **платну підтримку**. Self-hosted залишається безкоштовним, але без managed-безпеки й SLA.
